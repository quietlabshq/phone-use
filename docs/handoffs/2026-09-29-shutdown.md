## Task 13 API and constraints to preserve

`PhoneUseRemote.HTTPService` owns bounded sessions and tasks and calls the existing `MCPServer` tool conversion and `ToolDispatcher`. `HTTPListener` is a separate SwiftNIO adapter. The service uses SDK typed request/result values rather than the SDK HTTP server transport because that transport retains unbounded SSE replay state and has cancellation/lifecycle limitations. Real SDK HTTP client interoperability is tested.

- `HTTPService.handle(RemoteHTTPRequest, deadline:) async -> RemoteHTTPResponse`; headers are ordered tuples. The optional deadline is `MonotonicClock.now` seconds, clamped to 120 seconds.
- Host and Origin remain explicit allowlists. Public relay Host/Origin must be allowed deliberately, not bypassed. `allowHost` exists; configure origins at service creation.
- Every HTTP request authenticates; scope/revocation rechecked after discovery, queue wait, immediately before input. Remote discovery hints are suppressed.
- Server-generated session IDs, credential-bound sessions, equal JSON-RPC IDs isolated by session, duplicate active IDs rejected. JSON responses, GET 405, no SSE/replay or automatic mutation retry.
- Explicit caller Task cancellation cancels its owned invocation and waits for cleanup. A direct HTTP socket disconnect deliberately does not cancel an action. Loss after execution may mean unknown outcome.
- 64 connections/sessions, 32 active requests, 8 waiting per phone/32 globally, 16 KiB headers, 256 KiB request body, 8 MiB response. Whole macros hold the phone lock. Control lease is credential/session-bound and lasts 60 seconds from mutation completion; reads do not renew it.
- `POST /leases/release` with the authenticated session releases its own phone lease; DELETE idle `/mcp` closes its session. Same service/dispatcher must serve direct and relay routes.
- `serve --simulator --port 0 --credentials-directory PRIVATE_DIR` works. Default credentials path is `~/.config/phone-use/credentials`, a private child directory. Non-loopback cleartext requires `--allow-remote --insecure-development-http`. Repeated `--allowed-host`/`--allowed-origin` supported.
- Global ownership is held through service/backend shutdown. Credential create/list/revoke commands remain usable during daemon operation. CLI/stdio phone operations fail clearly while daemon owns access.

Wire decisions are provisional until both languages' golden fixtures/tests agree:

- `POST /daemon/{macID}/pair` with a single-use pairing Bearer token; return a separate daemon secret once. `GET /daemon/{macID}/connect` upgrades to WS with daemon Bearer secret.
- Relay sends `{v:1,type:"connected",generation:UUID}`. Daemon hello includes generation, revision 1, credential digests + exact phone-ID scopes + Unix-millisecond expiry or null, and catalog `{version,hash,tools}` from actual `MCPServer.tools`.
- Credential updates are replace-all, increasing revision within generation; omit revoked credentials. Poll/reload the local credential store so CLI changes propagate. Local HTTPService always revalidates even if edge metadata is stale.
- Dispatch has UUID dispatch/request IDs, generation, absolute Unix-millisecond deadline, method, local path `/mcp` or `/leases/release`, header tuples and raw base64 body. Convert deadline to continuous local time and clamp to 120 seconds. Reject expired before input.
- Responses: result_start, sequential result_chunk, result_end; failure distinguishes not_started from unknown. No automatic resend of in-flight commands. Consider JSON-RPC error status 200 for forwarded unknown outcome so clients retain the error body, while preserving exact original ID.
- Max 32 pending/Mac and 8 MiB aggregate retained payload, including response bytes until consumed; 256 KiB requests and bounded frames/results. No offline queue. Backpressure and late/stale frames must be tested.
- Daemon URLSessionWebSocketTask: explicit max message size, HTTPS/WSS except explicit loopback test mode, no secret URLs, refuse unsafe redirects, capped exponential reconnect jitter, stop on revoked credential. Disconnect cancels queued work through shared service; running cancellation cleans up with unknown outcome. Direct HTTP survives all relay outages.
